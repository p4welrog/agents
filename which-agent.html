    How to use “Which Agent Is It?”

    What is this for?

    Russell & Norvig describe four basic agent programs, each adding one capability to the previous one, and a way to make any of them learn. Here you practise both directions:

    • Identify: from a description of behaviour, decide which architecture is behind it.
    • Build: from a list of requirements, assemble the simplest architecture that can meet them, and watch its diagram appear.
    The four architectures in one minute
    • Simple reflex: condition → action on the current percept only. No memory.
    • Model-based reflex: keeps an internal state, updated with a model of how the world evolves and what its actions do. Still chooses by rules.
    • Goal-based: knows which situations are desirable and predicts “what happens if I do A?” to reach them (search, planning).
    • Utility-based: rates states on a scale, so it can trade off conflicting goals and weigh probabilities: maximises expected utility.
    • + Learning: any of them can get a critic (feedback against a fixed standard), a learning element (makes improvements) and a problem generator (suggests exploratory actions).
    Identify mode
    1. Read the case. Look for evidence: does it remember anything? Does it have a destination? Does it weigh several things? Does it get better over time?
    2. Pick the architecture and answer “Does it learn?”, then Check.
    3. The feedback underlines the clues in the text, coloured by what they reveal (legend below the text).

    Choose the simplest architecture that explains the behaviour. A thermostat could be built as a utility maximiser, but nothing in its behaviour requires it.

    Build mode
    1. Read the task and its requirements.
    2. Switch components on or off in the left column. The diagram and the name of the architecture update as you go; warnings show inconsistent combinations (e.g. goals without a way to predict outcomes).
    3. Check design marks each requirement ✓ or ✗ and flags components that are not needed: a more complex agent is slower, harder to build and harder to trust.
    The components
    • State: what the agent currently believes about the world, including what it can't see now.
    • How the world evolves: changes that happen without the agent (other cars move, dirt appears).
    • What my actions do: effects of the agent's own actions. Needed both to update the state and to predict “what if I do A?”.
    • Goals: descriptions of desirable situations (binary: reached or not).
    • Utility: a number for how good a state is; allows trade-offs and expected values.
    • Critic, Learning element, Problem generator: the learning agent's parts.

    Condition–action rules are drawn automatically when there are no goals or utility: then the rules decide.
