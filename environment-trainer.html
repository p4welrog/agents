    How to use the trainer

    What is this for?

    Every agent design starts with the task environment. Here you practise the two first steps from Russell & Norvig, ch. 2: specifying the environment with PEAS and classifying it along seven dimensions that decide which kind of agent you need.

    How it works
    1. Pick a scenario from the list (or go through them in order with Next scenario).
    2. PEAS: write your own answer first. Only then press Compare with model answer. There is no automatic grading; the point is to notice what you missed.
    3. Classify: choose one option per dimension and press Check. Every dimension gets an explanation.
    4. Try again clears your choices for that scenario.

    Scenarios marked from the textbook follow AIMA's tables; new case ones apply the same reasoning to modern systems.

    How answers are marked
    • ✓ correct: matches the textbook answer.
    • ✓ defensible: a genuinely contested case; any defensible option counts, and the arguments for each side are shown. Read them: in an exam, the justification is what earns the points.
    • ✗ not quite: compare your reasoning with the explanation.

    A dot in the list shows your result: ● all seven right, ● some wrong.

    Each dimension has its own button with definitions, examples and the usual traps.

    Common traps
    • Unknown map ≠ unknown environment. Not seeing the state is partial observability; not knowing what your actions do is unknown.
    • An opponent does not make the world stochastic. Chess is deterministic and multi-agent.
    • Moving things are not agents. Only entities that optimise something depending on you are.
    • ‘Sequential’ here is not ‘not parallel’. It means decisions have long-term consequences.
    • The answer depends on how you frame the task. Diagnosis from one set of symptoms is episodic; diagnosis with tests and follow-up is sequential. State your framing.
    Writing a good PEAS
    • P: describe desired outcomes in the world, not behaviours (‘clean floor’, not ‘moves around a lot’). Name the trade-offs (fast vs. safe).
    • E: include other agents and anything that varies (weather, users).
    • A / S: concrete devices or channels: for software agents, API calls and messages count.
