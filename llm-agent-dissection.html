    How to use “Dissect an LLM Agent”

    What is this for?

    The lecture's vocabulary (percepts, actions, internal state, goals, built-in knowledge) was invented long before large language models, and it still describes them precisely. Here you take real-looking runs of LLM agents apart and map every step onto that vocabulary.

    The goal is to see that an LLM agent is a model-based, goal-directed agent whose agent program is a language model, whose actuators are tools, and whose internal state is mostly its context window.

    How it works
    1. Pick a run on the left. Each card is one step: system prompt, user message, the model's reasoning, a tool call, a tool result, a memory write, or a step of the harness (the software running the model).
    2. Click a card: the diagram on the right shows where the step's label belongs in the agent loop, and the meter shows how full the context window is at that moment.
    3. Choose a label for every card and press Check labels. Some steps genuinely have two defensible labels; both are accepted and the explanation says why.
    4. Answer the questions under the run. Each has an explanation.
    The six labels
    • Goal: what the agent is asked to achieve; desirable states of the world.
    • Built-in knowledge: what the designer put in before the run: system prompt, rules, tool descriptions (and the model's trained weights).
    • Percept: new information arriving from the environment: tool results, user messages, errors.
    • Deliberation: the agent program at work: interpreting percepts, predicting “what happens if I do A”, choosing.
    • Action: changes or queries the environment through an actuator: a tool call, a message to the user.
    • State update: something kept for later decisions: notes, summaries, a memory file.
